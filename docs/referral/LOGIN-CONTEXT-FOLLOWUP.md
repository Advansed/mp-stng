# Совместимость Windows receipt / Linux — 20.11.2026

Продолжение f44dd03, без переделки авторизации и без публикации приложения.
Перед началом origin/main сверена: f44dd03, владелец сообщил, что Коля пока
не собирает/не выпускает приложение. Новый код требуется включить в его сборку.

Единственное дополнение входа: optional referral_invite_token берётся из уже
сохранённого native Android контекста Install Referrer/deep link. Ожидание SDK/
хранилища ограничено1.5сек; при ошибке обычный запрос идёт без параметра. iPhone
контекст не передаёт. Пароль/служебные токены не добавляются в referral API.

Подготовленный Windows-патч удаляет поле перед единственным штатным SQL-вызовом
и на успешном ответе добавляет referral_login_receipt: подписанные серверные
id/phone, exp120сек, jti и SHA256 приглашения. Linux сверяет подпись и ранее
зафиксированное согласие на странице приглашения. Это закрывает прежний пробел
Android, но требует согласованного выпуска обоих серверных компонентов.

Существующий backend игнорирует неизвестное JSON-поле через свой OPENJSON контракт;
патч дополнительно удаляет его перед SQL. Ответы старых серверов без receipt не
создают дополнительных referral-запросов. Контрольные SQL-вызовы в production не
выполнялись. Результат — APP_LOGIN_CONFIRMED, не PHONE_VERIFIED/новая регистрация.

iPhone использует прежний Linux SMS claim без возврата на сайт. ЕСИА не изменена
и отдельного подтверждения для неё пока нет. APP_FIRST_OPEN/установка не выводятся
из факта входа. Магазинные установки остаются отдельным тестом Коли на устройствах.

Проверки: TypeScript, React production build, Android unit tests и unsigned
bundlePlayRelease/assembleRustoreRelease повторно пройдены. Исходники runtime
не меняют подпись/номера версий. Секреты и публикация не включены.

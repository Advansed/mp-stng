# Приглашение в установленном приложении СТНГ

## Что реализовано

Обработчик находится в корне React-приложения, вне сменяющихся экранов входа и личного кабинета. Capacitor `App.getLaunchUrl()` получает ссылку холодного запуска; `appUrlOpen` — ссылку уже запущенного приложения. Подписка создаётся до чтения стартовой ссылки. ESIA удаляет только собственную подписку.

Принимается только точная ссылка `https://referal.aostng.ru/r/{token}` с 43 символами base64url, соответствующими генератору PWA. Иные хосты, схемы, пути, query и fragment игнорируются. Код не переходит по полученному URL и не отправляет его на произвольный сервер.

Первое приглашение сохраняется отдельно от профиля в localforage (`stng-referral/invitations`, ключ `pending-invitation-v1`) на 30 дней. Повторная доставка не продлевает срок; новое приглашение не подменяет первое. Операции сериализованы. Просроченная или повреждённая запись удаляется при следующем чтении. Ошибка хранилища не блокирует вход. Очистка данных приложения, удаление приложения или вытеснение хранилища ОС могут удалить приглашение.

Это **локальный контекст, а не доказательство участия или зачёт сотруднику**. Код не записывает ФИО, телефон, пароль, токен авторизации или ID абонента и ничего не отправляет на сервер реферальной системы. Отсутствует привязка к кешированному профилю: в действующем клиенте токен появляется и при незавершённой регистрации, а локальное `auth=true` не доказывает серверную проверку SMS.

## Пользовательский путь

1. Сотрудник создаёт отдельное приглашение в PWA.
2. Если обновлённое приложение установлено и домен подтверждён ОС, ссылка открывает его. Приглашение сохраняется, обычный вход/регистрация продолжаются без изменения.
3. Если приложения нет, открывается публичная страница PWA. Магазин выбирается на этой странице, а не внутри отсутствующего приложения.
4. После установки абонент повторно открывает **исходную ссылку**. Переход через магазин сам по себе не переносит приглашение в новую установку.

Для автоматического сохранения через установку нужны отдельная интеграция Google Play/RuStore Install Referrer и согласованный сценарий iOS. Они не входят в этот исходный пакет. Старые установленные версии не изменяются после push в Git.

## Что ещё нужно для достоверной статистики

Публикация PWA и native association-файлов, подписанные сборки и проверка устройств описаны в NATIVE-RELEASE.md. Нельзя объявлять текущий пакет полным E2E регистрации.

Будущий согласованный серверный контракт должен:

- Получать приглашение только после явного участия абонента и проверять его существование, срок, отзыв и сотрудника.
- Устанавливать абонента из проверенной сервером сессии, не из переданных клиентом ID/телефона/флага успеха. Не передавать существующий bearer-токен Windows новому домену без согласованного доверенного обмена.
- Отдельно проверять серверное завершение регистрации и предшествующее состояние аккаунта. Существующего абонента не засчитывать новым; `PHONE_VERIFIED` не заменяет `REGISTRATION_CONFIRMED`.
- Фиксировать подтверждённое обращение мобильного клиента отдельно от регистрации. Назвать событие `APP_FIRST_OPEN` можно только при определённом серверном правиле дедупликации; клиентское поле platform не доказывает установку или подлинность приложения.
- Давать идемпотентную квитанцию; уникальность зачёта абонента и приглашения обеспечивать транзакцией. При потере ответа сначала читать состояние операции, не повторять регистрацию.
- После проверенной квитанции удалять локальное приглашение; при смене пользователя не переносить подтверждённую атрибуцию автоматически.
- Привязку ЛС получать отдельным проверенным серверным событием.

**Ни один такой endpoint сейчас не подключён.** Статистика PWA по открытиям/переходам в магазин не становится статистикой установок. Windows, SQL, регистрация, SMS и действующая авторизация этим изменением не меняются.

## Откат исходников

Откатить только коммит этого пакета обычным `git revert`, не сбрасывать другие изменения. Уже опубликованный native-релиз потребует нового подписанного релиза для отката; Git сам по себе приложение на телефоне не меняет. Никакие production-сервисы этим пакетом не перезапускаются.
